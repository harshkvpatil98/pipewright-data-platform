# Pipewright 1.0.0

The first release with a version number. Everything before it is in the
[changelog](../../CHANGELOG.md), by phase.

Pipewright brings data in from files, databases and apps, cleans it in a
visual Studio, checks it, runs the work on a timetable, and delivers it to
databases, storage, BI tools and dashboards. It runs on your own servers.
[What it is for, and what it is not for](../positioning.md).

## In this release

**For the people who use it**

- A guided first run: sample data, recipe templates, a checklist, help on
  every page, and a finished example in one click.
- The Studio: the data in the middle, steps beside it, settings where you
  click, undo, one search for every step and tool.
- Checks that set failing rows aside, alerts when a dataset's numbers cross
  a line, incidents that reach email, Slack and webhooks, and one Activity
  list of everything that happened in a project.
- Charts, dashboards, scheduled reports, share links, and dashboards shown
  inside other sites with links that run out.
- Every version of every dataset kept, readable, comparable and restorable.

**For the people who run it**

- Single sign-on (OIDC, tested against Keycloak), two-factor sign-in, roles
  per project, row and column policies on every read, network allow-lists,
  files encrypted at rest, a full audit log in sentences.
- Files in a local volume or any S3-compatible bucket; several gateways and
  workers share one database and one bucket.
- Long work (uploads over 25MB, large deliveries, database copies) on a
  background worker, workflows that retry and pick up where they failed,
  rate limits, OpenTelemetry traces, and the server's limits listed on
  System status.
- Docker Compose and a Helm chart, installed on a clean Kubernetes cluster
  in CI on every change.

**For the people who build on it**

- A REST API with its reference in the product (`/docs`) and as of this
  release in [`docs/api/openapi.json`](../api/openapi.json).
- A Python client and a `pipewright` command line generated from it.
- Signed webhooks, project bundles to move work between projects, and
  signed embed links a site's server can make per customer.

## Upgrading

From any earlier build: back up first (`scripts/backup.sh --verify`), then
`alembic upgrade head` (the Helm chart's migration job does it). The database
goes to revision `0059_activity`. Settings new since the last builds:

| Setting | Where | What it does |
| --- | --- | --- |
| `MAX_UPLOAD_SIZE_BYTES` | gateway | Up to 200MB by default; the worker needs about nine times the file's size in memory |
| `WORKFLOW_LEASE_SECONDS` | gateway | How soon a run whose worker stopped is noticed (180) |
| `WEB_BASE_URL` | gateway | Where people open Pipewright, for links in emails and embeds |
| `EMBED_ALLOWED_ORIGINS` | web | Sites that may show an embedded dashboard |
| `TRUSTED_PROXY_HOPS` | gateway and web | Proxies in front, so each person's address is read correctly |

## Known limitations

Stated in full in the [README](../../README.md#known-limitations) and
[docs/HANDOFF.md §7](../HANDOFF.md#7-known-gaps--stated-not-hidden). The ones
a buyer asks about first:

- 161 of the 211 connectors have not run against the real vendor, and say so.
- Okta and Entra ID have not been run (no tenant); Keycloak is tested.
- SAML is absent.
- Charts and the Assistant's analyses read datasets of up to 500,000 rows;
  larger data is grouped or filtered with a recipe first. Checks read any
  size.
- English is the one language.

## Checked for this release

`npm run verify` (ruff, the Python test bundle, web tests, ESLint,

walked at two widths with no problem found; the Helm chart installs on a
clean cluster in CI. Cold-user sessions with people outside the team are
described in [the protocol](../cold-user-sessions.md) and have not yet been
